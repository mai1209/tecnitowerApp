Flujo Tecnitower
Control Remoto Cloud

La app se conecta a un backend en la nube. El backend usa EMQX para comunicarse con un agente local dentro del local del cliente. Ese agente habla con el Elfin por red local y el Elfin convierte a RS485 para llegar al TC900E.
Arquitectura Operativa

Nube

App Movil / APK El usuario ve temperaturas, estado y setpoint.
↓
Backend Tecnitower Autenticación, controladores, comandos y validaciones.
↓
EMQX MQTT Broker Transporta comandos y respuestas entre nube y local.

Local del Cliente

Agente Local Mac, Raspberry o mini PC conectada al mismo WiFi/LAN.
↓
Elfin EW11A IP local, puerto 502, puente Modbus TCP hacia RS485.
↓
TC900E Controlador físico conectado por RS485 / Modbus.
Comando desde la app
→
Respuesta de vuelta a la app

Secuencia

Lectura: App → Backend → EMQX → Agente Local → Elfin → TC900E → Elfin → Agente Local → EMQX → Backend → App.

Escritura: App → Backend → EMQX → Agente Local → Elfin → TC900E. Luego la confirmación vuelve por el mismo camino.

Nota: en esta arquitectura el Elfin no se conecta directamente a la nube. Quien se conecta a EMQX es el agente local.
